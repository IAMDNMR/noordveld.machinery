# One Agentic E-Commerce screen: implementation and test matrix

Date 2026-10-12, functional test run completed 2026-10-13. Branch `aftersales-homepage`.

## What was wrong
Signed out, the menu item "Agentic E-Commerce" opened the introduction page, whose "See it work" step opened **Agentic Shopping** (`/agentic-shopping`, "What do you need?"). Signed in as an End User, the same item opened the **Commerce Assistant** (`/commerce`, "What can I help you with?"). These are two different screens with two different engines: Agentic Shopping (`POST /agent/recommend`, public) finds parts, compares price and delivery and hands off to the cart; the Commerce Assistant (`POST /commerce/agent`, signed-in only) answers orders, shipments, warranty and part questions from the user's own records.

## What was changed
| Area | Change |
|---|---|
| Navigation | "Agentic E-Commerce" opens `/agentic-shopping` for visitors and End Users (`primaryNav`, `navFor`). Order Processor navigation is unchanged (it keeps Commerce Assistant). Footer unchanged. |
| `/commerce` | Order Processors keep the assistant screen (their workspace). End Users and visitors are redirected to `/agentic-shopping`, keeping the query string, so bookmarks still work. |
| Routing in the backend | `POST /agent/recommend` now also returns `commerce_domains`: the order, shipment, warranty or part questions the request contains that Agentic Shopping does not answer (`commerce_domains()` in `app/commerce_agent/agent.py`, using the Commerce Agent's existing rules; no language model; nothing read except a part number's id). Agentic Shopping's own engine, ranking and delivery logic are unchanged. |
| One screen | When `commerce_domains` is not empty, the Agentic Shopping result shows the Commerce Assistant's answer for those journeys only (`CommerceAnswerPanel`: the same `/commerce/agent` API, contexts, evidence views and clarification options; no second input box). A request that is not a parts request at all (e.g. "Where is my shipment?") is answered entirely there; a combined request shows the recommendation and, beneath it, "Also in your request · Warranty". |
| Sign-in | A visitor asking an order, shipment or warranty question sees "Sign in for your orders, shipments and warranty"; the existing sign-in brings them back to the same request (`next=/agentic-shopping?q=…`). |
| Examples | The screen keeps its own description and Agentic Shopping examples exactly as before sign-in and after; order, shipment and warranty questions are typed into the same input. |
| Cart | Unchanged: Agentic Shopping's own explicit "Add to cart" into the existing Parts Store cart (CartContext), then checkout. No second cart, no order is created. |
| Routing fixes found by the tests | "Which parts are included in my shipment?" is a shipment question, not a part search; order-status phrasings ("Has my order shipped?", "status of my order") route to logistics; "shipping to <unknown place>" no longer shows the user's unrelated shipment. |
| Fixes from the functional test run | "Show me my order" / "my orders" routes to the customer's own records; an order with no shipment lists its recorded order lines; "Do you have NVM-1050-HY in stock?" answers the part's recorded stock (`PART_STOCK`, the discovery engine's own availability rule, depot detail hidden from customers) instead of reading the part number as an unknown machine; an order question beside a part search is looked up instead of answered "no shipment for the replacement". |
| Language service unavailable | If the shopping agent's language service fails (e.g. daily quota), a request containing order, shipment, warranty or part questions still gets those answers from the records, with a notice that price and delivery comparison is unavailable; other requests return 503 as before. |

Retained and still reachable directly: `/commerce` for Order Processors, the Commerce Agent API and engine, the Parts Store cart and checkout, Parts Intelligence, My Orders, the introduction page `/agentic-commerce/`.


## Same interface
Signed-out and signed-in experiences use the same Agentic Shopping implementation: one route (`/agentic-shopping`), one component (`AgenticShoppingPage`), one backend (`POST /agent/recommend`), one cart (`CartContext`), one checkout (`/parts-store/checkout`). A browser check (Playwright) compared the two: identical heading, input, placeholder, button, examples and cart button; identical recommendation and result structure for the same request. The functional suite was therefore run once against the shared implementation, and authentication, authorization and customer isolation were tested separately (Security/isolation rows S1–S8, plus the sign-in rows).

The only difference is by design: order, shipment and warranty answers (the commerce panel) need sign-in; a visitor sees the sign-in prompt and is returned to the same request. In the cart, a visitor's cart is kept in the browser and an End User's on the server, both through the same `CartContext`.

## Fabricated or unsupported responses
None found in the final run. Every part, fitment, price, stock figure, route, ETA, order line, shipment status and warranty decision shown came from a graph record. Unknown parts, machines, destinations, orders, shipments and claims were answered as not found or with a question. Overdue status used the recorded planned ETA with no new ETA invented, and potential routes were labelled as not assigned to any shipment. Before the fixes, two answers were misleading but not fabricated: Atlantis showed the user's unrelated shipment, and an order question beside a part search was answered "no shipment for the replacement". Both are fixed and covered by tests.

## Known limitations
* "Show me my order" for a customer with several orders answers with the customer's one recorded shipment (the Commerce Agent's existing resolution) rather than listing the orders.
* A clarification asked by the commerce part of a combined request has no option buttons when the records offer none; the user adds the detail to the request and asks again.
* Delivery to a destination outside Agentic Shopping's recorded destinations (e.g. Lagos) is not computed by Agentic Shopping; the potential routes recorded for that place are shown instead, labelled as not assigned to any shipment.
* Agentic Shopping needs the language service to interpret a request (Groq free tier, 1000 requests a day). When it is unavailable, order, shipment, warranty and part questions are still answered from the records; part recommendations are not.
* Answers about orders, shipments and warranty need sign-in; visitors get the sign-in prompt, not the data.
* All operational data is synthetic demonstration data; no carrier, ERP or warranty system is connected.
