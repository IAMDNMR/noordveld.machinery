# Application composition and preview verification — 22 October 2026

## Findings and implemented changes

- The template selected in a project already affects the older runtime's presentation, not its business schema. The Screens stage nevertheless presented competing template recommendations and keyword matches as capability coverage. The normal Screens stage now presents the application itself; the standalone library and stored selections are preserved.
- Frontend planning silently assigned omitted steps to an existing page. This changed trace labels without a deliberate page design. That shortcut was removed. Invalid plans are returned to the model with the rejected plan and all omissions; bounded repairs must produce a valid plan before any source is written.
- An application inventory now derives task views, record lists/details and create/edit responsibilities from saved processes, entities and related records. Responsibilities may share a workspace. Unknown bindings, omitted responsibilities and bindings to unrelated entities/steps are rejected. Optional explanations of real automated decisions are permitted. This is planning evidence, not behavioral certification.
- The model receives compatible visual patterns from multiple library resources as optional composition guidance. These never import sample records, business policies, routes or capability claims.
- The four-domain selection cutoff and the frontend's 14-file, 25-file-schema and 40-page-schema ceilings were removed. Explicit, independently evidenced secondary domains remain eligible; generic actor/feature words alone do not select a domain. Source-size and execution-time safety limits remain explicit failures rather than truncation.
- Generated React page bindings now appear in traceability and change-impact reports. Reports explicitly distinguish declared page bindings from tested behavior. The application inventory is exported with the ordinary design manifests.
- The baseline preview's outer content policy blocked its inner scripts; its bootstrap also failed to escape `<` in business text. The preview now runs its intended isolated scripts with network access blocked and escapes bootstrap content. Preview context selects a working project role without changing runtime authentication.
- Screens now use a full-height canvas before and after source generation. Full screen fills the viewport. The optional Design direction input and repeated generation setup card were removed. First generation starts once for authorized editors; saved interfaces open directly. The preview dialog does not initiate builds. Explicit visual chat/voice requests can request a checked rebuild without changing business rules.
- Job progress now remains active until the versioned database save completes. Failed jobs report their result and do not silently restart on reopening. The source checkpoint and rejected plan are retained locally for recovery. Business project revisions and successfully built source remain in the configured project store.
- The live after-sales build exposed malformed repair edits containing strings instead of objects. Repair parsing now rejects malformed/ambiguous edits without crashing or replacing every matching occurrence. A failed targeted patch falls back to the existing checked rewrite path.
- The baseline client contains wide boards/tables inside their own scrollers and uses an accessible mobile navigation menu. Apply/Dismiss controls reflect the assistant's actual busy state.
